## 1. 発注者が明示した仕様（A）

- 入力: 商品マスタ Excel（列: 商品コード, 商品名, 現在庫, 単価）
- 入力: 入出庫 CSV 複数（列: 日時/日付, 商品コード, 区分, 数量）※後に伝票番号・明細ID追加確定
- 入庫は加算、出庫は減算
- 複数 CSV を1回で処理
- 結果 Excel: 商品ごとの最新在庫＋集計（今回入庫・今回出庫・処理後在庫）
- Win11、Python は依頼者インストール可
- UX: マスタ指定 → CSV フォルダ指定 → 実行（初回/継続の明示選択を追加確定）
- 規模: マスタ 500〜2,000、CSV 100〜1,000 行 × 1〜10 ファイル、日本語
- 納品: Python コード、ライブラリ一覧、README、実行方法、テスト結果
- 商品マスタを壊さない・消さない

## 2. 発注者に確認済みの仕様（B）

- 現在庫は、今回読み込む CSV が未反映の値
- 重複除外: キー「伝票番号＋明細ID」。今回 CSV 群内＋過去実行分
- 同一キーで商品コード・区分・数量・日付のいずれかが異なればデータ矛盾 → **処理停止**（自動採用しない）
- 明細 ID 空欄: 在庫更新に使わずエラー一覧（確定）
- 未登録商品コード: 反映せずエラー一覧
- マスタ内コード重複: **処理停止**＋エラー
- 欠損・不正値: その行は処理せずエラー一覧
- 負在庫: 計算は行い警告表示。自動補正しない
- 数量は正の整数。区分は「入庫」「出庫」のみ
- 商品コードはマスタ・CSV・集計・履歴すべてで文字列扱い。先頭ゼロ保持。既に `408` になっているものを `00408` と推測補完しない。空白除去程度は可、値そのものは変えない。商品 B 正式コードは `00408`
- 集計列: 商品コード / 商品名 / 現在庫 / 今回入庫 / 今回出庫 / 処理後在庫
- 対象シート名: `商品マスタ`
- 単価列があれば変更せず保持
- 保持必須: シート構成・列順・見出し・列幅・セル基本書式・既存数式
- 数式の現在庫セル: **上書きしない**。当該商品は自動更新対象外。集計には表示し「現在庫が数式のため未更新」を明示。数式の再計算・書き換え不要
- 入力ファイルは変更しない。結果は別 Excel（例: `商品マスタ_更新結果_YYYYMMDD_HHMMSS.xlsx`）。同名衝突時は上書きせず日時／連番で新規
- 次回入力マスタ = 前回の更新結果 Excel（毎回オリジナルは使わない）
- 履歴は結果 Excel 内シート `処理履歴`
- 初回: オリジナルマスタ、履歴なしで `処理履歴` 新規作成。利用者が「初回」を明示選択
- 継続: 前回結果 Excel。履歴なし／破損／必須項目不足 → 停止。利用者が「継続」を明示選択
- 履歴登録は在庫反映＋結果保存成功行のみ。エラー行・数式除外行は履歴に入れず再取込可
- 実験は文章仕様で審査。実案件では実装前に匿名化 Excel/CSV 共有想定
- 報酬 ¥22,000・納期 5 営業日（契約日から、土日祝除く）正式確定
- （⑥レビュー反映）結果同名上書き禁止・原子的保存・矛盾時全体停止・履歴必須列・エラー/警告分離・商品コード推測禁止

## 6. 入力形式

### 商品マスタ（Excel）

- シート: `商品マスタ`
- 列: 商品コード, 商品名, 現在庫, 単価（他列・他シートは保持）
- 商品コード: 文字列（例 `00125`, `00408`）

### 入出庫 CSV

- 列: 伝票番号, 明細ID, 日付, 商品コード, 区分, 数量
- 区分: `入庫` / `出庫`
- 数量: 正の整数
- 文字コード・区切り: 実装時に utf-8-sig / cp932 等をテストで確認し README に記載（実案件はサンプルで確定）

## 7. 出力形式

- 別 Excel: `商品マスタ_更新結果_YYYYMMDD.xlsx`（日付形式は実装時 README 固定）
- 既存シート構成をコピー／保持したうえで在庫更新結果を反映
- 集計情報（商品コード単位の今回入庫・出庫・処理後在庫）を含む
- シート `処理履歴` 最低保持項目: 伝票番号, 明細ID, 日付, 商品コード, 区分, 数量, 処理日時
- **エラー一覧**: 未登録コード、欠損、不正値、明細ID空欄など（元ファイル名＋行番号）
- **警告一覧**: 数式現在庫、負在庫など（元ファイル名＋行番号）

## 8. 正常時の処理

1. 利用者が初回／継続を選択
2. マスタ Excel と CSV フォルダを選択して実行
3. CSV 全ファイル読込 → 履歴照合 → 重複除外 → 集計
4. 数値の現在庫セルのみ更新。数式セルはスキップして警告
5. 結果 Excel を保存（成功時のみ履歴登録）
6. 処理履歴・エラー／警告を出力

## 9. 異常時の処理

- マスタ内商品コード重複: 全体停止
- 同一キーで内容矛盾（商品コード・区分・数量・日付のいずれか不一致）: **その実行全体を在庫更新せず停止**。一部だけ更新してから止まるのは禁止
- 継続モードで履歴欠落・不備（シート不存在／必須列欠損／重複キー異常／読取不能）: 全体停止。自動修復しない
- 行単位エラー（未登録、欠損、明細ID空など）: その行スキップ＋**エラー一覧**（元ファイル名＋行番号）
- 数式現在庫・負在庫: **警告一覧**（元ファイル名＋行番号）。負在庫は計算継続、数式セルは未更新
- 結果保存失敗: 処理済み／履歴登録としない。中途半端ファイルはエラー明示

## 10. 上書きルール

- 入力マスタ・入力 CSV は上書きしない
- 結果ファイル名が既に存在する場合は **上書き禁止**
- 衝突時は日時付きで新規作成する（例: `商品マスタ_更新結果_20261027_153000.xlsx`）または連番。勝手上書きは不可
- 結果 Excel の保存に失敗した場合、処理履歴だけ進んだ状態を作ってはいけない。**結果保存成功後にのみ処理完了扱い**
- 中途半端なファイルが残る場合はエラーとして明示

## 11. 元データ保護ルール

- 選択された入力 Excel / CSV は読み取りのみ
- 履歴を元マスタへ書き込まない

## 12. 重複・欠損・不正データの扱い

- 重複: 伝票番号＋明細ID（今回＋履歴）
- 矛盾: 停止
- 欠損・不正・明細ID空・未登録: 行除外＋エラー一覧
- マスタ重複コード: 停止

## 実装解釈（⑥承認時の注記）

- 処理履歴は結果 Excel 内シートのため、「結果保存成功後に履歴登録」は次の意味で実装する: 履歴を含めた完成 Workbook をメモリ上で作成 → 新規ファイルとして正常保存 → 保存成功した時点で履歴登録済みとみなす。保存後にもう一度履歴を書いて再保存する必要はない。
